# T1110 — Brute Force (SSH Password Guessing)

**ATT&CK reference:** https://attack.mitre.org/techniques/T1110/
**Sub-technique:** T1110.001 (Password Guessing)
**Status:** Attack recorded. Rule and test pending.

## Summary

A password guessing attack was simulated against SSH on our own lab VM, using a throwaway account and a small wordlist. The goal was to generate real `sshd` failed authentication log lines to build and test a detection rule against.

## Environment

- Target: our own Ubuntu lab VM (`ubuntuVortex`), not a shared or production system
- Attacker and target are the same machine (loopback), run by Abdulmujeeb
- Test account: `testvictim`, created only for this exercise and deleted afterward
- Tools: OpenSSH server, Hydra 9.2
- Date: 2026-11-07

## Steps performed

**1. Install SSH server and Hydra**

```
sudo apt install -y openssh-server hydra
```

**2. Create a throwaway test account**

```
sudo adduser testvictim
```

Account `testvictim` (UID 1001) created with its own group and home directory. No real user credentials were used.

**3. Build a small wrong-password wordlist**

```
printf "123456\npassword\nqwerty\nletmein\nadmin\nwelcome\n" > ~/words.txt
```

**4. Run the brute force attempt**

```
hydra -l testvictim -P ~/words.txt -t 2 ssh://127.0.0.1
```

Result: Hydra tried 6 password guesses against `ssh://127.0.0.1:22` (2 tasks in parallel) and completed with **0 valid passwords found**, confirming every login attempt failed as intended. Run started and finished at 2026-11-07 21:29:41–21:29:48 UTC.

**5. Capture the log lines**

The first capture attempt returned nothing because `grep` treated `/var/log/auth.log` as a binary file (`grep: /var/log/auth.log: binary file matches`), so the redirect produced an empty file. This was fixed by forcing text mode with `-a`:

```
sudo grep -a sshd /var/log/auth.log | tail -n 40 > ~/raw.log
```

**6. Sanitize the log before committing**

Loopback address and hostname were replaced with safe placeholders:

```
sed -e 's/127\.0\.0\.1/192.0.2.10/g' -e "s/$(hostname)/labhost/g" ~/raw.log > logs/T1110/ssh_bruteforce_auth.log
```

**7. Clean up the lab**

```
sudo deluser --remove-home testvictim
sudo systemctl disable --now ssh
```

The test account was removed along with its home directory, and the SSH service was disabled on the lab VM.
